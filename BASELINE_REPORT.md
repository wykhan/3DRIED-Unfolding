# Five-method baseline validation

Status: **DELIVERED PARTIAL MATRIX — INDEPENDENT REVIEW PENDING** on `baseline/ista-net-validation`.
This report supersedes the old five-method display matrix, which contained
both RM-kernel Ini-ISTA and a provisional CV-ISTA name. That old experiment
remains historical evidence, not the current method roster.

## Fixed scope

The methods are basic BP, reference RMA, true-adjoint complex ISTA, original
ISTA-Net, and frozen accepted RMIST-Net. The single receiver is MATLAB Rx1 /
Python index 0. Data are `[z=200,x=407,fast_time=256]`, with spacings 2 mm / 1 mm.
The processing carrier is 78.8 GHz (metadata start frequency 77 GHz), sampling
rate 5 MHz, chirp slope 70.295 THz/s, sampled bandwidth 3.599104 GHz, instrument
delay 0.62516 ns, spatial grid 512 square, and reference MATLAB bins 12--24.
`configs/baseline_3dried.yaml` retains the source acquisition parameters and
the legacy runner settings. `configs/ista_net_baseline.yaml` and
`scripts/run_imaging_baseline.py` define the new experiment and method roster.
Reference one-based range labels and all accepted coordinates are preserved.

## Implementation

- `basic_bp.py`: explicit candidate-point and observation loops, geometric
  distance, complex phase compensation, direct sum. No FFT convolution,
  sensitivity normalization, adaptive weights, or fast BP. A range-profile
  interface includes elementary complex linear interpolation. Propagation
  convention must be verified before using that interface on Hammer.
- `sar_operator.py`: the accepted RM forward with physical aperture mask,
  and its actual Hilbert adjoint. A single known constant rescales both A
  and y so the RMS spectral gain is one. It does not normalize from Hammer
  data or alter image coefficients. The strict RMIST inverse is unchanged.
- `ista_net.py`: unshared original ISTA-Net phases, each with gradient data
  consistency, learned scalar step/threshold, conv-ReLU-conv analysis,
  shrinkage, conv-ReLU-conv synthesis, and threshold-free symmetry residual.
  It has two real/imaginary input/output channels, 32 features, 9 phases,
  and no ISTA-Net+ residual connection. The reference topology is from the
  [authors' original implementation](https://github.com/jianzhangcs/ISTA-Net-PyTorch/blob/master/Train_CS_ISTA_Net.py).
- Adaptation choices: adjoint initialization instead of a fitted CS Qinit;
  step expressed relative to the known spectral Lipschitz bound; signed
  identity plus small random perturbation initializes the transforms for
  sparse complex inputs. These are documented SAR initialization choices,
  not claimed paper-reported settings. The original Xavier option exists.
- `train_ista_net.py`: independent procedural train/validation/test splits,
  validation-selected checkpoint, test evaluated after checkpoint selection.

## Training protocol

Each rate has a separate model and the same disjoint scene splits: 128 train,
32 validation, 32 test; seeds 20261027/20271027/20281027. Each full-size scene
contains 1--6 complex points, amplitudes U(0.5,1), independent phases U(0,2pi),
x ROI [-0.20,0.15] m, z ROI [-0.10,0.30] m, and a bin from 12--24.
Echoes are generated by the accepted RM model, cropped/masked to the physical
aperture, with exactly 20 dB observed-sample circular complex AWGN.
This is a model-matched point baseline, not a full FMCW acquisition simulator.

Adam uses learning rate 1e-4, batch one, 20 epochs, symmetry weight .01,
shuffle seed 20261028. Reconstruction and symmetry losses share a target
energy scaling; target phase is retained. Every run has a one GPU-hour cap.
These are new baseline choices and do not change any RMIST hyperparameter.

## Interpretation gates

PASS in the entry-point metrics means finite completed reconstruction with
the declared measurement/model checks. It does not mean independent review
or superiority. No untrained model participates in rankings. New-mask RMIST
is SKIPPED unless explicitly requested as an unvalidated diagnostic. BP on
RM-generated data is cross-model and has uncalibrated coherent-sum gain;
its complex NMSE is not used as an algorithm ranking. A budget-interrupted
BP never returns a partial image as a valid reconstruction.

M8 supports scale mismatch; M9's four fixed normalizers degraded the required
real-data proxies. No historical normalization is automatically adopted.
Hammer has no voxel GT; no Hammer NMSE/PSNR/SSIM is reported. ISTA-Net Hammer
inference is sim-to-real, with no Hammer-based training or parameter tuning.

## Hammer: no demonstrated learned improvement

No raw-scale adjustment, Hammer-based tuning, image labels, fine-tuning or
M9 normalization was used. Observed-sample residuals were:

| Height rate | RMA | ISTA200 | ISTA-Net, sim-to-real |
|---|---:|---:|---:|
| 100% | 0.06467155 | 0.77297894 | 1.32347755 |
| 70% | 0.05685657 | 0.77707025 | 1.37768143 |
| 50% | 0.05518355 | 0.78372944 | 1.57259260 |
| 30% | 0.05229785 | 0.80738907 | 1.49039496 |

The Hammer remains visible, but ISTA-Net suppresses substantial content and
has worse data consistency than RMA. No true Hammer NMSE/PSNR/SSIM is reported.
Energy/entropy are descriptive only. Residuals at different rates constrain
different observed samples; their decrease at a lower rate does not show
that throwing away measurements improves image quality.

## BP cost and remaining physical gate

The explicit phase-only direct sum passes coherence, complex interpolation,
and full-aperture local analytic point controls. The local candidate grid is
9x9 at reference bin17. Single-point localization error is zero at all four
rates; two equal-phase points 6 mm apart satisfy the fixed valley control.
This is a single-frequency control, not full raw FMCW/Hammer acceptance.

The 100% control took about 4.59 s for 81 candidates and 81,400 observations.
Linear extrapolation to 13x512x512 candidates is about 54 CPU-hours. The main
runner uses an explicit five-second BP diagnostic cap and never reports a
partial image as a reconstruction. Full-FOV BP remains SKIPPED. The raw
phase/range convention, including the inherited one-bin label offset, needs
an independent physical control before full Hammer BP can be promoted.

## Solver and resolution qualifications

The first validation scene was evaluated at fixed 200/2000/20000 ISTA steps,
without selecting parameters on test or Hammer data. At 50%, its NMSE fell
from 0.96768540 at 200 steps to 0.59721994 at 20000. Thus the 200-step table
is a budget-limited baseline, not a well-converged reference or a proof of
intrinsic algorithm superiority.

The fixed noiseless, equal-phase RM two-point controls at 2/4/8/16 mm all
met the declared local-peak/3 dB valley criterion. They are model-matched
controls and must not be quoted as universal or physical 3DRIED resolution.
PSLR/ISLR use nearest-local-minimum mainlobe bounds for single-point axis
cuts only. Multi-target sidelobe metrics are explicitly SKIPPED.

## Timing protocol and artifacts

Each timed reconstruction covers 13 slices, two warmups and five repeats,
with the median saved. CUDA methods synchronize and include returning the
complex output to CPU. Loading, range FFT, operator/model construction,
file I/O and plotting are excluded. Hardware: Intel Xeon Gold 5317 CPU and
RTX 4090. RMA uses NumPy CPU; ISTA/ISTA-Net use CUDA. These mixed-device
application timings do not establish an intrinsic algorithm speedup.

Hammer 50% medians: RMA 0.131826 s (CPU), ISTA200 0.940962 s (CUDA),
ISTA-Net 0.136661 s (CUDA).
